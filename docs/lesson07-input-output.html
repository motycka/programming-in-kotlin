Command line arguments

Command line arguments are passed to the program when it is executed from the command line.

We have been using main method with args: Array<String> parameter, but we have not explained what they are and how they are used.

When you run a Kotlin program from the command line, you can pass arguments to the program. These arguments are treated as strings and are stored in the args: Array<String> array.

We can also read input from console using readLine() function. 

						
							fun main(args: Array<String>) {
								println("Received ${args.size} arguments:")

								for ((index, arg) in args.withIndex()) {
									println(" $index = $arg")
								}

								println("\nEnter your name:")
								val name = readLine()
								println("\nHello, $name!")
							}

Paths and Resources

Classpath

Paths and resources

Understanding how to access files and resources in Kotlin applications.

To access a file, we need to obtain its path reference as URI (Uniform Resource Identifier),
which is a string of characters used to identify a resource.
You can also use URL, which is a specific type of URI that identifies a resource on network location.

There are two types of paths:

  • Absolute path

    is a full path to the file or directory

    While accessing a file by its absolute path is easier, it is not very practical, because it will differ from one system (computer) to another. For this reason, using relative paths is more common (and reliable).

  • Relative path

    is relative to the current working directory

    This might seem obvious when writing the code, but keep in mind that in Java program context, the current working directory is not always the same as the directory in which the Java application is located.

Working with resources

Accessing files that are distributed with the source code.

In Kotlin applications, files that are distributed with the source code are conventionally located in the src/main/resources directory, or in the src/test/resources directory for test resources.

Files in these directories are included in the application's classpath and can be accessed using ClassLoader or Class methods.

  • In this example, we are using object {}.javaClass::getResource to obtain a resource.
  • We are calling getURI on the resource to get its full path.
  • Since the resource may not exist, we are obtaining the URI using null safe operator ? and checking if the returned value is not null with the requireNotNull function.
  • We use File class to work with the actual file.
  • It is always a good idea to do all this in a try-catch-finally block to make sure we handle all IO errors and free system resources should they be raised. 
						
							val fileName = "characters.csv"

							val resource = object {}.javaClass.getResource("characters.csv")

							val uri = requireNotNull(resource?.toURI()) {
								"$fileName file not found"
							}

							try {
								val file = File(uri)
								// work with resources
							} catch (e: IOException) {
								// handle ecxeptions
							} finally {
								// close resources
							}

Working with Files

kotlin.io & java.io

Working with Files

Kotlin provides a kotlin.io library of functions to work with files which is actually an extension of Java libraries.

This is where it gets a little messy. When we work with files in Kotlin, we need to understand a little bit about Java history.

Java comes with two libraries for working with files and directories:

  • java.io (legacy)
    Provides classes for reading and writing files, and working with directories. This library contains the File class that represents a file or directory path.
  • java.nio.file ("modern")
    Provides a more modern way to work with files and directories and was introduced in Java 7.

Kotlin also provides its own functions for working with files in the kotlin.io package. These functions are implemented as extension functions on top of the Java libraries, specifically the File class.

Reading Files

Reading Files

Kotlin provides a whole library of File extension functions for working with files. Few to mentions are:

  • readText
    Reads the entire content of the file as a String.
  • readLines
    Reads the file content as a list of lines.
  • forEachLine
    Reads the file line by line and processes each line with a given action.
  • readBytes
    Reads the entire content of the file as a byte array.
  • copyTo
    Copies the file to the specified destination.

Reading Files

Reading files in Kotlin is straightforward, but we still need to be mindful of few possible problems. 
								
									import mu.KotlinLogging
									import java.io.File
									import java.io.IOException

									private val logger = KotlinLogging.logger {}

									fun main() {

										val fileName = "characters.csv"
										val resource = object {}.javaClass.getResource("characters.csv")
										val uri = requireNotNull(resource?.toURI()) { "$fileName file not found"}

										try {
											val file = File(path)

											if (file.exists()) {
												logger.info { "Reading file: ${file.absolutePath}" }
												file.readLines().forEach {
													logger.info { it }
												}
											} else {
												error("characters.csv file not found")
											}

										} catch (e: IOException) {
											error("Error reading the file: ${e.message}")
										} finally {
											logger.info("File reading finished")
										}
									}
  • We are using File class to create a file object from a resource (URI).
  • We are checking if the URI exists, since the class loader might not find the resource.
  • We are also checking if the file exists, since the file might have been deleted or moved.
  • We are surrounded the file reading code with try-catch-finally block.
    • It is a good idea to catch IOException when working with files.
    • It is also a good idea to have a finally block when working with system resources such as files.

Reading Files

Buffered Reader

In addition to file reading functions mentioned, Kotlin also provides BufferedReader class, which you can obtain by calling bufferedReader() on a file object.

The purpose of bufferedReader is to provide efficient reading text data by buffering input. This reduces the number of I/O operations, which can significantly improve performance, especially when dealing with large files. 

						
							import java.io.File
							import java.io.IOException

							fun main() {
								val path = "example.txt"

								try {
									val file = File(path)

									// Reading from the file using bufferedReader
									file.bufferedReader().use { reader ->
										reader.forEachLine { line ->
											println(line)
										}
									}

								} catch (e: IOException) {
									println("An error occurred: ${e.message}")
								}
							}

Writing Files

Writing Files

Some of the kotlin.io functions to write files are:

  • writeText
    Writes the specified text to the file.
  • writeBytes
    Writes the specified byte array to the file.
  • writeLines
    Writes the specified lines to the file.
  • appendText
    Appends the specified text to the file.
  • appendBytes
    Appends the specified byte array to the file.
  • appendLines
    Appends the specified lines to the file.

Writing Files

								
									import mu.KotlinLogging
									import java.io.File
									import java.io.IOException
									import java.time.ZonedDateTime

									private val logger = KotlinLogging.logger {}

									fun main() {

										val path = "characters-copy.csv"

										try {
											val file = File(path)

											if (file.exists().not()) {
												file.createNewFile()
											}

											file.writeText(ZonedDateTime.now().toString())

											file.appendText("\nHello Kotlin!")

										} catch (e: IOException) {
											error("Error writing to file: ${e.message}")
										} finally {
											logger.info { "File reading finished" }
										}

									}
  • This time, we are using relative path to create a file. It will be created in our project root.
  • We are checking if the file exists, and if not, we create it.
  • Again, we surround the file writing code with try-catch-finally block to catch any IO exceptions and to free system resources.

Writing Files

Buffered Writer

Similarly, for reading operations, Kotlin provides BufferedWriter class, which you can obtain by calling bufferedWriter() on a file object.

The purpose of bufferedWriter is to provide efficient writing of text data by buffering the output. This reduces the number of I/O operations, which can significantly improve performance, especially when dealing with large files. 

						
							import java.io.File
							import java.io.IOException

							fun main() {
								val path = "example.txt"

								try {
									val file = File(path)

									// Writing to the file using bufferedWriter
									file.bufferedWriter().use { writer ->
										writer.write("Hello, World!\n")
										writer.write("This is an example of bufferedWriter.\n")
									}

								} catch (e: IOException) {
									println("An error occurred: ${e.message}")
								}
							}

Other File Operations

Other File Operations

Other file operations Kotlin makes available for us include:

  • exists - Checks if the file exists.
  • absolutePath - Returns the absolute path of the file.
  • canonicalPath - Returns the canonical path of the file.
  • isFile - Checks if the file is a regular file.
  • isDirectory - Checks if the file is a directory.
  • canRead - Checks if has read permissions.
  • canWrite - Checks if the file has write permissions.
  • canExecute - Checks if the file execute permissions.
  • setReadonly - Sets the file's read permission to be radable.
  • setReadable - Sets the file's read permission to given value (boolean) either for all or for owner only.
  • setWritable - Sets the file's write permission to given value (boolean) either for all or for owner only.
  • setExecutable - Sets the file's execute permission to given value (boolean) either for all or for owner only.
  • lastModified - Returns the time the file was last modified.
  • setLastModified - Sets the time the file was last modified.
  • delete - Deletes the file.

Input and Output Stream

Input and Output Stream

Working with InputStream and OutputStream classes.

When working with programs and libraries, you may come across code that uses InputStream and OutputStream classes.

These classes are used to read and write data from and to a source, such as a file, network connection, or memory.

  • InputStream is an abstract class that represents an input stream of bytes.
  • OutputStream is an abstract class that represents an output stream of bytes.
						
							import java.io.FileInputStream
							import java.io.FileOutputStream
							import java.io.IOException

							fun main() {

								val inputStream = FileInputStream("input.txt")
								val outputStream = FileOutputStream("output.txt")

								try {

									val buffer = ByteArray(1024)
									var bytesRead: Int

									while (inputStream.read(buffer).also { bytesRead = it } != -1) {
										outputStream.write(buffer, 0, bytesRead)
									}

								} catch (e: IOException) {
									println("An error occurred: ${e.message}")
								} finally {
									inputStream.close()
									outputStream.close()
								}
							}
